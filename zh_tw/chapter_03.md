# 第 3 章：系統設計面試框架（加強版）

## 1. 章節核心

建立固定作答流程，讓你面對不同題目都能穩定輸出。

## 2. 六步驟框架

### Step 1：需求澄清

- 核心功能是什麼？
- MVP 範圍到哪裡？
- 目標使用者與規模？

### Step 2：非功能目標

- 延遲目標（P50/P95/P99）
- 可用性（SLA/SLO）
- 一致性需求（強一致/最終一致）
- 合規與安全需求

### Step 3：高層架構

- 請求入口、核心服務、資料儲存、非同步管線。
- 先畫主幹，再談細節。

### Step 4：資料模型與 API

- 關鍵實體、索引、主鍵設計。
- API 的冪等性與版本策略。

### Step 5：瓶頸與優化

- 熱點、鎖競爭、單點故障。
- 快取、分片、讀寫分離、批次與非同步。

### Step 6：風險與取捨

- 哪些指標會先壞？
- 故障時怎麼降級？
- 為何選 A 不選 B？

## 3. 面試時間分配（45 分鐘參考）

- 0~8 分鐘：需求對齊 + 估算
- 8~20 分鐘：高層設計
- 20~35 分鐘：深挖 2 個關鍵點
- 35~45 分鐘：可靠性與取捨總結

## 4. 高分關鍵

- 每個決策都對應到前面的需求或估算。
- 不是只說技術，還要說成本與運維代價。
- 能明確分辨「現在版本」與「未來演進」。
